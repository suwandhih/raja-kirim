# AGENTS.md — Expedisi

This file is the primary instruction document the AI agent reads on every turn. Keep it up to date as the project evolves: when files move, dependencies change, or new conventions are introduced, update the relevant section below.

## Reuse and modularity rules
- Before adding UI or feature code, search for existing pages, components, layouts, modules, hooks, services, utilities, and types.
- Pages should compose layouts, modules, and shared components; they should not own major reusable functionality.
- When a feature is used twice, extract it to a shared component, layout, hook, service, or module before adding the second usage.
- Treat requests to copy, mirror, or replicate as refactor requests: extract the source implementation, update the original call site, then add the new call site.
- Put customer-deployable product capabilities in `src/modules/<feature>/` with a public `index.ts`; add `manifest.ts` when routes, permissions, navigation, dependencies, or feature flags matter.
- For intranet/digital-workplace apps, headers/navigation belong in layouts or shared components; people search, information concierge, global search, document libraries, policies, news, events, approvals, and dashboard widgets belong in modules.

## Stack
- Situs statis HTML, CSS, dan JavaScript browser; tidak ada backend, bundler, package.json, atau lock dependensi aplikasi pada impor asli.
- Satu situs Raja Kirim: `/` mengarah ke `/raja-kirim/`; jangan pisahkan menjadi layanan atau ubah framework. Seluruh HTML, CSS, skrip, dan data demo berada dalam `raja-kirim/`.
- Profil Foundry `node-24` hanya untuk tooling. Manifest npm menambahkan `serve@14.2.8` sebagai devDependency server statis; tidak menambahkan backend. Pertahankan `package-lock.json` hasil instalasi dan gunakan `npm ci` setelah lock tersedia.
- Bright Cargo look v1 is shared across all four pages through generated `src/styles/design-tokens.css` and editable `src/styles/brand.css`. Keep this static-stack exception: use semantic `bc-` primitives, not a React/Tailwind/shadcn migration.

## Conventions
- Konfigurasi runtime ada di `.cdf/runtime.json`; lifecycle standar npm (`dev`, `check`, `build`) ada di `package.json`. `PORT` disediakan platform; jangan tentukan port tetap.
- Pemeriksaan: `node scripts/static-site.cjs check`. Build statis: `node scripts/static-site.cjs build`. Pemeriksaan menjalankan `scripts/kalkulator-tests.cjs` dan `scripts/penawaran-tests.cjs` (unit Node/VM tanpa browser) untuk rumus, validasi, penyimpanan, payload quotation, penggantian pelanggan/sanitizer/hash tab, dan regresi 36 kombinasi Perbandingan harga.
- `/raja-kirim/kalkulator.html` memakai modul data beku `tarif-contoh.js`; muat sebelum `harga.js`/`kalkulator.js`. Pengaturan kalkulator disimpan di localStorage `raja-kirim-kalkulator-v1`, terpisah dari harga vendor. Semua angka adalah simulasi. API murni `window.RajaKirimKalkulator` menyediakan `defaults`, `validateInput`, `validateSettings`, `calculate`, `compare`, `loadSettings`, dan `saveSettings`; `compare` mengembalikan `{ok, results}` yang berisi rute, moda, ukuran, total/rincian USD, kurs, transit, dan selisih tanpa pembulatan. Jangan menghitung ulang melalui render untuk integrasi surat.
- Modul bersama `raja-kirim/penawaran.js` (`window.RajaKirimPenawaran`) membuat/memvalidasi payload versi 1 (Kalkulator negara, rute Indonesia) dan versi 2 dengan `sumber: 'perbandingan'` (Perbandingan harga, rute Jakarta). Kedua format memakai kunci `raja-kirim-penawaran-v1`; pilihan terbaru mengganti data sebelumnya. `sourceLabel(payload)` mengatur label "Data dari Kalkulator negara"/"Data dari Perbandingan harga" di surat. Muat `tarif-contoh.js` → `penawaran.js` → `harga.js` pada `index.html`, dan data → penawaran sebelum `kalkulator.js` atau `surat.js`. `createComparisonPayload` memvalidasi hasil terpilih tanpa menghitung ulang tarif; `handoffComparison` hanya membuka `surat.html#dokumen` setelah penyimpanan berhasil. Hanya quotation mengganti rute/layanan/berat/total/rincian lewat sanitizer, bukan pelanggan tersimpan atau tanda terima. Jangan duplikasi validasi payload di halaman. Setiap string payload maksimal 300 karakter. Tanpa payload, rincian bernilai `—`.
- Perbandingan harga (`raja-kirim/harga.js`) hanya untuk satu negara ↔ Jakarta: sisi tetap berlabel "Jakarta, Indonesia", kartu/ringkasan memakai "Jakarta". Tetap 3 vendor terurut berdasarkan total USD; Rupiah kecil = total × `RajaKirimData.kurs`, bukan kurs tersimpan kalkulator. Ketiga kartu dapat dipilih melalui klik/tap, radio native, dan tombol panah; membuka rincian biaya tidak mengganti pilihan. Setiap render memilih termurah kembali, tanpa menyimpan pilihan antar-muat ulang. Hasil render terakhir dan indeks pilihan memperbarui `#selection-summary` (aria-live) serta aria-label tombol `#create-quotation`. Tombol membawa pilihan terakhir (nama ekspedisi, transit, total USD/Rupiah, rincian kirim/lokal) ke surat; perubahan formulir yang belum dibandingkan tidak mengubah data kiriman. Kegagalan data/penyimpanan tampil di `#quotation-status` dan tidak memindahkan halaman. Selisih USD/hari memakai hasil yang sama dibanding termurah; daftar `vendor.keunggulan` beku berisi 2–3 klaim contoh berlabel simulasi, juga untuk nama vendor udara. Kalkulator negara tetap membandingkan antarnegara seperti semula.
- Desain C pada Perbandingan harga memakai override di akhir `raja-kirim/harga.css`, seluruh selektor dibatasi `body.comparison-page` agar CSS bersama tidak mengubah kalkulator. Banner diperdalam dari token agar teks putih memenuhi AA; penekanan visual/fokus mengikuti `offer--selected`, sementara termurah tetap bertanda `offer--best`/badge "Harga terendah". Badge "Terpilih", radio `checked`/`aria-checked`, dan ringkasan selalu sinkron. Badge moda berbeda, dan meter dekoratif memakai total ÷ total tertinggi tanpa mengubah biaya. Uji brand memeriksa cakupan selektor, breakpoint 1280/390, kontras gradasi dan primitif; ini bukan uji render browser.
- Pemeriksaan HTTP (tanpa browser): `node scripts/static-site.cjs http <alamat-preview>` setelah build dan Preview aktif.
- Build menyalin hanya 16 berkas publik ke `dist/` (13 berkas Raja Kirim + 2 stylesheet bersama + pengalihan `index.html`). Sajikan `dist/`, jangan seluruh repository; `serve.json` menonaktifkan directory listing. `serve.json` membatasi `cleanUrls` ke dua direktori situs dan memakai `trailingSlash: true` agar URL direktori selalu berakhiran `/`, sementara halaman `.html` tidak dialihkan ke subdirektori yang merusak aset relatif. Tambahkan berkas publik baru ke allowlist `scripts/static-site.cjs`.
- Styling order on every page: managed `src/styles/design-tokens.css` → editable `src/styles/brand.css` → page CSS. Never edit generated `src/styles/design-tokens.css`, `tailwind.design-system.preset.ts` or managed brand assets. Shared `bc-` classes own skip links, headers/nav, buttons, cards, badges, alerts, labels/controls and radio tiles; page CSS keeps layout and intentional print/dark-theme overrides. New static and JS-rendered actions must use the same primitives; do not restore legacy button/card/nav copies.
- Colours must come from token variables; derive tints/shadows with `color-mix()`, never literal hex/rgb values. Native canvas and editing commands resolve tokens with `getComputedStyle`; standalone PDF windows snapshot the token values and fonts so they need no stylesheet network request. Print does not depend on coloured backgrounds.
- Radio tiles keep an accessible visually hidden native radio followed by a span. Nunito/Montserrat load from Google Fonts with token system fallbacks.
- Final styling regression checks live in `scripts/brand-tests.cjs`, called by both check/build: token-only public CSS/JS, shared actions, comparison controls, print token snapshots, PNG colours/fonts and export failures. These are Node/VM unit tests, not browser rendering tests. Review layout at 1280px/390px; keep the calculator table and document tabs in their contained scrollers.
- Halaman utama `/` hanya menjadi pengalihan aksesibel ke `raja-kirim/` dengan tautan cadangan; jangan menduplikasi isi atau implementasi Raja Kirim. Navigasi `Daftar pelanggan` menuju `surat.html#pelanggan`.
- Modul `raja-kirim/pelanggan.js` (`window.RajaKirimPelanggan`) dimuat sebelum `surat.js`: validasi kontak, kontak/saluran utama, migrasi data pelanggan lama tanpa mengganti kontak atau riwayat, pembuatan pesan, pelengkapan contoh idempoten, dan kotak pesan satu pelanggan (8 pesan/halaman). Simpan bundle versi 2 pada kunci lama `raja-kirim-surat-v1`; tujuan pesan adalah snapshot, tujuan lama yang tidak tersimpan harus tetap kosong/ditandai, jangan ditebak dari kontak terbaru. Fax dan alamat masuk template dokumen melalui sanitizer. `scripts/pelanggan-tests.cjs` dijalankan oleh check/build. Tidak mengirim email/WhatsApp/fax sungguhan.
- Tidak perlu akun atau API key. Google Fonts memerlukan internet, dengan font sistem sebagai fallback. Seluruh alur bisnis tetap simulasi; data pelanggan tetap di localStorage browser.
- Perubahan sumber statis perlu build ulang dan restart Preview karena tidak ada HMR. Jangan jalankan server melalui shell; gunakan kontrol Preview Foundry.
- Demo publik memakai `.github/workflows/pages.yml`: push hanya ke branch remote `main` pada `suwandhih/raja-kirim`, Node `24.19.0`, `npm ci`, dan `npm run build` (termasuk seluruh check/uji). Unggah hanya `dist/` ke GitHub Pages; jangan pernah menerbitkan akar repository atau Library. Source Pages harus GitHub Actions, proteksi environment tetap dihormati, dan push memerlukan koneksi Git serta izin workflow yang sah. Petunjuk pemilik dan alamat tujuan ada di bagian Demo publik README; jangan mengklaim sudah online hanya karena build/push berhasil.

- When adding a new framework or runtime dependency, append it to **Stack**.
- Keep instructions concise — link to deeper docs rather than duplicating them.
